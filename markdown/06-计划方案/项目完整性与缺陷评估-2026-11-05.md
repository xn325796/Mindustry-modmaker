## 二、缺陷清单

### B1【Blocker · 验证链路】夹具探测误命中，全量测试 14 失败

- 证据：`FixtureProject.hasMetaFile`（`FixtureProject.java:60-67`）只看文件名是否存在，不解析内容、不要求 `content/`。`Mindustry-160.7/tools/extra-schemas/mod.json` 是 Mindustry 自带的 schema 片段（内容为 `doc`/`amount`），位于工作目录父级 3 层内，于是 `probe()` 返回它。
- 触发：项目旁边任意一层出现名为 `mod.json` 的文件夹（这次是参考源码 `Mindustry-160.7`），然后跑测试。
- 后果：`RoundTripTest` 4 条、`StabilityTest` 5 条、`AuthoringTest` 1 条、`RealModFixtureTest` 1 条、`LiveEditProbe` 1 条、`UiSmokeTest` 1 条、`RealModImportTest` 初始化 1 条失败；报错形如 `mod name is empty`、`the fixture has no planet record`。金标准往返（字节级保真）这套最重要的回归测试实际处于停摆。`App.java:114` 已说明普通启动不再自动打开夹具，所以目前不影响用户运行时；但"记住上次项目"这类后续功能一接上就会打开假项目。
- 最小修复：`hasMetaFile` 改为"能解析出非空 `name`"（复用 `HjsonReader`/`ModMeta`），并给 `FixtureProjectTest` 加一条"假 mod.json 不被接受"的用例；同批把 `RealModImportTest` 的 `assumeTrue` 从"目录存在"收紧到"目录里有 content/"。约 20 行 + 1 条测试。
- 附带缺口：这台机器上已经没有真实模组夹具（`../mod` 与 `550WOS` 都不在），修好后这 20 多条夹具用例会转为跳过而不是通过。需要把真实模组放回 `../mod`，或用 `-Dmodmaker.fixture=<目录>` 指过去，往返测试才算真正恢复。

### H1【High · 文档可信度】三处说法与仓库现状不符

1. `README.md:21`、`build.gradle.kts:65`、`markdown/首页.md:22` 都写"471 用例 / 57 类，0 失败、28 跳过"。实测 466 执行 / 14 失败 / 5 跳过。这句话现在会让人以为测试是绿的。
2. `README.md:24` 和 `markdown/首页.md` 写"无 JVM 时 `run.bat` 回退 `dist/ModMaker` 便携包"。`run.bat` 里没有这段逻辑：没有 Java 就直接报错退出；有 Java 时走的是 `gradlew installDist` + 生成的 launcher，也不是文档说的 `gradlew run`。`make-portable.bat` 的开头注释同样复述了这个不存在的回退。
3. `markdown/首页.md:8` 的项目路径仍是 `Desktop\Mindustry\Mindustry-modmaker`，`:22` 的夹具路径是 `Desktop/game/Mindustry/mod`，两者都已不存在；`:45` 引用的 `be43896`、`14a2a0b`、`6fe3787` 在本仓库查不到（仓库已重建，只有 5 个提交，消息为 `1`、`2`、`add build`、`interesting`）。

- 触发：新人按 README/首页操作，或任何人根据"0 失败"判断可交付。
- 后果：照做即踩空；真实的红测试被文档掩盖。
- 最小修复：夹具修好后按实测数字改；`run.bat` 的便携回退二选一——实现（检测无 JVM 时启动 `dist\ModMaker\runtime\bin\java.exe`），或把文档和 `make-portable.bat` 注释改成事实。首页路径与提交号一并更新。

### M1【Medium · 上手成本】新克隆缺 `JDK25/` 时，Gradle 在启动阶段就报错

- 证据：`gradle.properties:6` 是 `org.gradle.java.home=JDK25`（相对路径，按启动目录解析）；`JDK25/` 在 `.gitignore` 里。`run.bat` 的提示写"JDK 21 or later"，而 `build.gradle.kts:37` 的 toolchain 是 25。
- 触发：`git clone` 后直接 `gradlew.bat test`（`JDK25/` 不存在），或在别的目录用 `-p` 调用。
- 后果：Gradle 在加载项目之前报 "Java home supplied is invalid"，堆栈与项目无关，新人很难定位。装 JDK 21 也救不了，反而被 `run.bat` 的提示误导。
- 最小修复：README 的"环境要求"写成两步（先放 JDK25 到项目根、再用任一 JVM 启动 gradlew），`run.bat` 的版本提示改成 25；可选：`gradle.properties` 里保留但加注释"缺失时改用 JAVA_HOME"不可行（属性无 fallback），所以更稳的是删掉属性、只留 toolchain + 文档说明。提交 365 MB 的 JDK 不建议。

### M2【Medium · 数据安全】自动保存与崩溃恢复仍然没有（上次 H2 未做）

- 证据：全仓仍无 `autosave`/`backup` 实现，只有退出前的未保存守卫。
- 触发：编辑过程中进程被杀、断电、JavaFX 崩溃。
- 后果：自上次手保存以来的编辑全部丢失；项目越大损失越大。
- 最小修复：复用 `ProjectIo` 的原子写，定时（如 2 分钟且有改动）落到 `modmaker/autosave/`（该目录本就不进导出），启动时若比项目新则提示恢复。验收：强杀进程后重启能恢复到最后一次自动保存。

### M3【Medium · 版本一致性】schema 仍标 160.5，且 `source` 指向已不存在的目录（上次 M4 未做）

### L1【Low · 可维护性】`ProjectController` 2370 行、9 个 UI 类仍无测试引用
